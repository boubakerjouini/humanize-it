# HumanizeIt — Full-Spectrum Audit

**Overall Health: 49/100.** A genuinely impressive solo-founder build whose monetization, trust, and data-safety core is not yet safe to charge money against — one focused week of fixes away from launch-ready, and dangerously unsafe to monetize until then.

## Executive Summary

HumanizeIt is a broad, well-crafted pre-launch SaaS: a 40-pattern in-house AI detector with real burstiness/TTR/Flesch math and a test suite, a multi-pass Claude Sonnet 4.5 rewrite pipeline, a polished light-mode UI, two strong long-form blog posts, programmatic SEO clusters, legal pages, a public `/api/v1`, an extension auth flow, and LemonSqueezy billing. For one person, the breadth and polish are well above average.

But nearly every specialist auditor independently surfaced the same small set of structural failures, clustered around **money, trust, and data safety**:

1. **Inverted quota model.** `/api/humanize` (the expensive Claude path) only checks `rewriteCount` for FREE users, never enforces or decrements `wordsUsed` for anyone, and PRO/TEAM carry `rewriteLimit: -1`. The cheap local `analyze` endpoint is the only place the word quota is touched. Combined with zero rate limiting and a hardcoded extension JWT fallback secret (`humanize-ext-secret-2026`) that lets anyone forge tokens for any user, the Anthropic cost ceiling is effectively infinite and publicly exploitable. A $9 plan against unmetered multi-pass Sonnet is structurally negative-margin.

2. **Fabricated / contradictory truth.** The "5-engine" detector panel (GPTZero/Turnitin/Originality/Copyleaks/Winston) is `Math.random` theater layered on the in-house score — yet the entire $9 promise rests on it. Pattern count is stated as 24, 37, and 40 (code ships 40). Social proof is invented (12,000+ users, 4.8/5, 2M+ documents) on a pre-launch product. The students page is explicit Turnitin-evasion marketing aimed at minors that directly contradicts the Terms.

3. **Operational fragility.** Every Vercel build runs `prisma db push --accept-data-loss` with no migrations directory — one careless schema edit silently drops paying customers' tables with no rollback. Zero error tracking. Non-atomic quota/redeem mutations race under concurrency. A root-layout `force-dynamic` strips static generation from the entire SEO surface the GTM plan depends on.

The verdict is not "this is bad" — it is "this is a strong product one focused week away from being safe to monetize, and unsafe to monetize until then."

## Top Priorities

1. **Meter and cap the humanize path atomically for all plans** (Billing & Monetization Integrity, 🔴 critical). *Why:* `/api/humanize` never enforces or decrements `wordsUsed` and PRO/TEAM are `rewriteLimit: -1`, so the costly Claude Sonnet path is unmetered on paid plans — making published 50k/200k limits fiction and unit economics negative as usage grows. *Action:* Add one `consumeWordQuota(userId, words)` used by `/api/humanize` AND `/api/v1/humanize`: after `checkAndResetQuota`, reject 402/429 when `wordsUsed + wordCount > plan.wordsLimit` (skip `-1`), then atomically increment via Prisma `updateMany WHERE wordsUsed + n <= limit` (treat `count === 0` as exceeded). Gate the Anthropic call on the successful increment.

2. **Replace `prisma db push --accept-data-loss` with a migration workflow** (Ops, Reliability & Observability, 🔴 critical). *Why:* `package.json:7` — every production deploy can silently drop paying customers' columns/tables with no history and no rollback. The single largest existential risk. *Action:* Baseline `prisma migrate dev` locally into `prisma/migrations`, commit it, change the build to `prisma generate && next build`, apply via `prisma migrate deploy`. Enable and test a Neon PITR/branch restore before the first cutover.

3. **Remove the hardcoded extension JWT fallback secret and fail closed** (Security & Access Control, 🔴 critical). *Why:* `lib/extension-auth.ts:3` falls back to `'humanize-ext-secret-2026'`, which is in the repo. Anyone can forge a Bearer token for any `clerkId` and spend your Anthropic budget under arbitrary users. *Action:* Delete the `|| 'humanize-ext-secret-2026'` fallback, throw at startup if `EXTENSION_TOKEN_SECRET` is unset, set a 32-byte random secret in Vercel, switch the signature compare to `crypto.timingSafeEqual`.

4. **Add per-user/per-key rate limiting on all Anthropic-backed endpoints** (Security & Access Control, 🟠 high). *Why:* No limiter exists despite `plans.rateLimit` and public docs promising it. A single actor (or the forged-token hole) can turn the Claude bill into a denial-of-wallet incident before $5K MRR. *Action:* Add `@upstash/ratelimit` (sliding window, free tier) keyed by `clerkId` for humanize/analyze and by `apiKeyId` for `/api/v1/*`, using `plan.rateLimit`; return 429 + Retry-After. Add an Anthropic monthly spend alarm.

5. **Fix the UpgradeModal dead upgrade link** (UX Flows & Activation, 🔴 critical). *Why:* `upgrade-modal.tsx:161` links `<a href=/api/checkout?plan=...>` but the checkout route only exports POST. Every upgrade click from the primary paywall dead-ends — losing the sale at peak intent. *Action:* Reuse the working POST flow (`fetch /api/checkout` with `{plan}`, then `window.location = data.url`) with a loading state, matching dashboard-nav/settings. Ship before any paid traffic.

6. **Stop the FREE 1/day rewrite limit from killing the first humanize** (UX Flows & Activation, 🔴 critical). *Why:* The editor auto-runs multi-pass humanize, but FREE allows one rewrite/day, so a free user's first and only activation moment fails mid-flow or pops an upgrade modal on pass 2. *Action:* For FREE, cap to a single pass that always returns a complete result and present it as the win; gate the up-to-3-passes messaging behind paid plans; if a later pass is blocked, keep pass 1's output visible with a non-destructive upgrade banner.

7. **Remove the root-layout `force-dynamic` to restore static SEO pages** (Frontend Architecture & Performance, 🟠 high). *Why:* `app/layout.tsx:12` strips static generation from `/`, `/compare/*`, `/use-cases/*`, blog and legal — hurting TTFB/CWV/crawl budget on the exact surface the SEO-led GTM depends on. *Action:* Delete line 12; set `dynamic` only on the `(dashboard)` and `(auth)` segments. Verify with `next build` that marketing pages show as Static/SSG.

8. **Kill the fabricated detector panel and contradictory claims** (Core Algorithm & AI Engine, 🟠 high). *Why:* `lib/engines.ts` is `Math.random` variance on the in-house score, presented as GPTZero/Turnitin/etc. The core "beats real detectors" promise is unvalidated and the on-screen proof is fabricated — false advertising plus a brand-killer for a detector-savvy audience. *Action:* Integrate one real detector API to power before/after honestly, or relabel the number as "HumanizeIt internal AI-likelihood (not a detector guarantee)" and remove per-engine scores. Build a small labeled corpus to report real, hedged efficacy.

9. **Reposition the students page and reconcile it with the Terms** (Legal, Compliance & Positioning Risk, 🟠 high). *Why:* The students page is explicit academic-fraud marketing ("Bypass Turnitin", "99%+ pass rate", "perfect for homework") aimed at minors, directly contradicting the Terms — the top deplatforming/payout-freeze/Chrome-Web-Store risk. *Action:* Reframe around "avoid false AI-detection flags on your own original writing", drop the bypass/99% language from H1/meta/body, add an age statement and acceptable-use stance, make Terms and marketing consistent.

10. **Make redeem codes safe: purge committed codes, atomic redemption, time-box plans** (Pricing & Packaging, 🟠 high). *Why:* `scripts/generated-codes.txt` is in the repo (free PRO/TEAM codes in plaintext); redemption is a non-atomic check-then-act and grants permanent unbilled paid plans — a direct, shareable MRR/cost leak. *Action:* `git rm` the codes file + gitignore + burn those DB rows; make redemption atomic via `updateMany WHERE usedCount < maxUses` in a transaction; store `planExpiresAt` so granted plans downgrade; ensure word metering applies to redeemed users.

## Quick Wins

- **Delete the root `force-dynamic` line.** Remove `app/layout.tsx:12` and move it to `(dashboard)`/`(auth)` segments; re-run `next build`. Minutes of work, large TTFB/CWV/crawl win.
- **Remove the hardcoded extension secret fallback.** In `lib/extension-auth.ts:3` drop `|| 'humanize-ext-secret-2026'`, throw if unset, set a random 32-byte secret in Vercel. Closes a full account-impersonation hole in one edit.
- **Purge the committed redeem codes.** `git rm scripts/generated-codes.txt`, gitignore `scripts/*.txt`, delete those code rows, switch `generate-codes.ts` to `crypto.randomBytes`. Stops free PRO/TEAM giveaways.
- **Fix the UpgradeModal CTA and broken OG image.** Change `upgrade-modal.tsx:161` to the POST checkout flow, and remove the explicit `og-image.png` references in `app/layout.tsx` (lines 34/45) so Next auto-wires the working dynamic `opengraph-image`. Recovers conversions and social-share cards.
- **Single-source the pattern count to 40 everywhere.** Derive the marketing number from `PATTERNS_CONFIG.length` and find/replace the 24/37 instances across page.tsx, compare, auth-modal, JSON-LD, OG image, and blog.
- **Guard humanize against empty/refusal output overwriting user text.** In `humanizeText`/`runClaudePass`, throw on empty or refusal responses and never persist `rewrittenText` when `humanizedText` is empty. Prevents silent destruction of paying users' content.
