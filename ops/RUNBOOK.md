## 📦 1. CHECKLIST DÉPLOIEMENT VERCEL

### Variables d'environnement à configurer (Vercel Dashboard → Settings → Environment Variables)

```
# Database (Neon)
DATABASE_URL=postgresql://...
DIRECT_URL=postgresql://...

# Auth (Clerk)
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_...
CLERK_SECRET_KEY=sk_...
NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in
NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up
NEXT_PUBLIC_CLERK_AFTER_SIGN_IN_URL=/dashboard
NEXT_PUBLIC_CLERK_AFTER_SIGN_UP_URL=/dashboard

# Payments (Stripe)
STRIPE_SECRET_KEY=sk_live_...
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_live_...
STRIPE_WEBHOOK_SECRET=whsec_...
STRIPE_PRO_PRICE_ID=price_...

# App Config
NEXT_PUBLIC_APP_URL=https://humanizeit.app
NODE_ENV=production
```

### Étapes de déploiement

- [ ] Merge de la branche `main` propre et testée
- [ ] Toutes les variables d'env configurées dans Vercel Dashboard
- [ ] Webhook Stripe configuré pour l'URL de prod (`/api/stripe/webhook`)
- [ ] Schema Prisma pushé sur Neon prod (`npx prisma db push`)
- [ ] Build local OK (`npm run build` sans erreurs)
- [ ] `vercel --prod` ou push sur `main` → déploiement auto
- [ ] Vérifier le deploy log Vercel (aucune erreur de build)
- [ ] Tester le flow complet en prod (signup → humanize → paywall → checkout)
- [ ] Vérifier que le domaine custom est pointé (DNS → Vercel)
- [ ] SSL actif sur domaine custom

## 📊 3. MONITORING POST-LAUNCH (48 premières heures)

### Ce qu'on surveille

| Métrique | Outil | Seuil d'alerte |
|----------|-------|----------------|
| Uptime | Vercel / UptimeRobot | < 99.5% |
| Erreurs 500 | Vercel Logs | > 5/heure |
| Temps de réponse | Vercel Analytics | > 3s |
| Inscriptions | Clerk Dashboard | Tendance |
| Conversions Free → Pro | Stripe Dashboard | Tendance |
| Webhook Stripe | Stripe → Logs | Échecs |
| DB Connections | Neon Dashboard | Saturation |
| Erreurs Prisma | Vercel Logs | N'importe laquelle |

### Process de monitoring

**Heure 0-6 (post-launch) :** Vérification toutes les 30 min
- Vercel Logs → chercher `ERROR`, `500`, `timeout`
- Stripe Dashboard → événements webhook reçus
- Clerk Dashboard → nouveaux users

**Heure 6-24 :** Vérification toutes les 2h
- Même liste + vérifier Neon usage (connexions, requêtes)
- Surveiller le taux de conversion sur la page pricing

**Heure 24-48 :** Vérification toutes les 4h
- Consolider les métriques
- Identifier les points de friction (où les users droppent)
- Rédiger le premier rapport "Day 1 Report"

### Commandes de diagnostic rapide

```bash
# Voir les derniers logs Vercel
vercel logs --prod --follow

# Tester l'API humanize
curl -X POST https://humanizeit.app/api/humanize \
  -H "Content-Type: application/json" \
  -d '{"text": "This is a test sentence generated by AI."}'

# Vérifier la DB
npx prisma studio  # En local pointant sur prod DATABASE_URL
```

### Accès & Secrets

> ⚠️ Ne jamais committer les secrets en clair. Toujours utiliser les variables d'env Vercel.

- **Neon :** `DATABASE_URL` dans Vercel env (projet `humanize-it`)
- **Clerk :** Dashboard → API Keys → copier `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` + `CLERK_SECRET_KEY`
- **Stripe :** Dashboard → Developers → API Keys → mode Live
- **Stripe Webhook :** Dashboard → Developers → Webhooks → endpoint `/api/stripe/webhook`

### Procédure d'urgence (site down)

1. Vérifier Vercel Status : https://www.vercel-status.com
2. Vérifier Neon Status : https://neonstatus.com
3. Checker les logs Vercel : `vercel logs --prod`
4. Si DB down → Neon Console → vérifier connexions actives
5. Si Stripe down → checker https://status.stripe.com
6. En dernier recours → rollback Vercel vers le dernier déploiement stable
